# D0 — Análisis del Sistema: Minimarket «La Esquina»

**Cliente:** Minimarket «La Esquina», San Vicente de Cañete
**Tipo de aplicación:** Aplicación web interna
**Usuario principal:** Cajero
**Fecha de elaboración:** 23 de octubre de 2026

---

## 1. Problema

El minimarket no lleva un control digital de ventas ni de stock, por lo que al final del día se desconoce cuánto se vendió y se queda sin productos de alta rotación.

---

## 2. Usuarios y qué hace cada uno

| Usuario | Acciones que realiza |
|---|---|
| **Cajero** | Registra productos y registra las ventas de los productos. |
| **Dueño** | Consulta los resultados: productos con stock bajo y ventas del día con el total vendido. |

---

## 3. Proceso actual y su dificultad

Hoy las ventas se anotan en un cuaderno y el stock se revisa mirando físicamente los estantes. Esta forma manual provoca que al final del día no se sepa cuánto se vendió y que el minimarket se quede sin productos de alta rotación sin detectarlo a tiempo.

---

## 4. Requisitos funcionales

**RF1 — Registrar productos**
El cajero registra cada producto con los siguientes datos: código, nombre, categoría, precio de venta, stock actual y stock mínimo.

**RF2 — Listar productos con alerta de stock mínimo**
El sistema lista los productos y resalta aquellos que están en o por debajo de su stock mínimo.

**RF3 — Registrar una venta de un producto**
El cajero elige un producto y la cantidad a vender. El sistema toma el precio de venta vigente, calcula el total de la venta, registra la fecha y la hora, y descuenta la cantidad vendida del stock del producto.

**RF4 — Listar las ventas del día**
El sistema lista las ventas realizadas en el día y muestra el total vendido del día.

---

## 5. Requisitos no funcionales

**RNF1 — Seguridad: acceso a datos con PDO y sentencias preparadas**
Toda interacción con la base de datos se realiza mediante PDO con sentencias preparadas para prevenir inyección SQL.

**RNF2 — Seguridad: token CSRF**
Los formularios que modifican datos incluyen un token CSRF para evitar falsificación de petición en sitios cruzados.

**RNF3 — Seguridad: salida escapada**
Toda información mostrada en la interfaz se escapa para prevenir ataques de tipo XSS (Cross-Site Scripting).

**RNF4 — Seguridad: credenciales en archivo .env**
Las credenciales de la base de datos y otros datos sensibles se almacenan en un archivo `.env` y no se incluyen en el control de versiones.

**RNF5 — Integridad de datos: transacción en la venta**
La operación de registrar la venta y descontar el stock se ejecuta dentro de una transacción de base de datos, de modo que ambas operaciones se completen juntas o se reviertan juntas.

**Stack tecnológico**
- PHP 8 orientado a objetos, sin frameworks.
- MySQL/MariaDB de XAMPP como motor de base de datos.
- Aplicación web servida desde el entorno local de XAMPP.

---

## 6. Reglas de negocio

**RN1**
La cantidad vendida debe ser mayor que cero.

**RN2**
No se puede vender más unidades de las que hay en stock.

**RN3**
El precio de venta no puede ser negativo.

**RN4**
El código de producto es único; no pueden existir dos productos con el mismo código.

**RN5**
La venta y el descuento de stock ocurren juntos o no ocurre ninguno (atomicidad de la operación).

## 8. Supuestos

- SUPUESTO la aplicación se ejecuta únicamente en el entorno local de XAMPP del minimarket y no se exponen a internet.
- SUPUESTO: normalmente un solo cajero usa la aplicación a la vez; aun así, la venta se protege con una transacción.
- SUPUESTO el producto tiene un único precio de venta vigente que se toma al momento de registrar la venta.
- SUPUESTO la categoría del producto se asigna de forma libre por el cajero al momento de registrar el producto.
- SUPUESTO el stock se gestiona únicamente a través del registro de ventas; no hay módulo de compras ni ajustes manuales de inventario.
- SUPUESTO el día laboral coincide con el día calendario (de 00:00 a 23:59) para el listado de ventas del día.
- SUPUESTO el archivo `.env` existe y contiene las credenciales correctas de la base de datos antes de ejecutar la aplicación.
- SUPUESTO: cada venta registra un solo producto; no hay ventas con varios productos (carrito)
- SUPUESTO: los precios están en soles (S/)
